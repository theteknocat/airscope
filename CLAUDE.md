# Airscope — project notes

Native Linux GUI (Rust, egui/eframe 0.37, glow) visualising Wi-Fi / Bluetooth / LAN around peter-pc as a radar. Repo: private `theteknocat/airscope`, branch `main`. Build `cargo build --release`; binary `target/release/airscope`. Plan: `docs/PLAN.md`. **Style and UI conventions: `docs/STYLE.md` — read before changing any screen** (visual over text, colour meaning, dates `MMM d, YYYY`, tooltips, responsive rules).

## Layout
- `src/data.rs` — collectors on threads publishing to `Arc<Mutex<Shared>>`: Wi-Fi via `nm.rs`, BlueZ device list via `bluez.rs`, LAN (neighbours via `net.rs`, mDNS via `mdns-sd` crate, stale devices pinged), OUI vendors (`Oui`: built-in `src/oui.tsv` < system `/usr/share/hwdata/oui.txt` < user `~/.config/airscope/oui.tsv`; `parse_oui` reads IEEE txt/csv, Wireshark manuf, plain TSV; header "Vendor list" button opens an import window — drop a file or paste a path; `AIRSCOPE_VENDOR=1` opens it at start). Regenerate built-in list: `scripts/gen-oui.sh [oui.txt]`. `Dev` (id = BSSID/MAC), `BtLink`.
- `src/hci.rs` — native Bluetooth HCI (kernel socket, read-only commands, no root): connections, AFH map, link quality, RSSI, TX power, remote version. Replaced `hcitool`. Test: `cargo test live_dump -- --ignored --nocapture`.
- `src/bluez.rs` — BlueZ over system D-Bus (zbus, blocking): one `GetManagedObjects` call gives all devices + properties (replaced `bluetoothctl`). Test: `cargo test bluez_dump -- --ignored --nocapture`.
- `src/nm.rs` — NetworkManager over system D-Bus (one `GetManagedObjects` at `/org/freedesktop`): cached scan results, channel/security text like nmcli, `request_scan`. Replaced `nmcli`. Test: `cargo test nm_dump -- --ignored --nocapture` (diffed against nmcli: identical).
- `src/nl80211.rs` — true Wi-Fi signal (dBm) per BSSID from the kernel's nl80211 scan cache over generic netlink (what `iw dev <if> scan dump` shows; no root, never scans). `data.rs` collector fills `Ap.dbm` from it (the kernel keeps scan results only ~30 s, so the collector remembers each BSSID's last real reading for 30 min); `wifi_dev` falls back to NM's percentage (`pct/2-100`, capped at -50 dBm) when it is missing (demo data, no wireless). Radar distance uses the real dBm, so strong nearby sources sit closer than before. Test: `cargo test nl80211_dump -- --ignored --nocapture`.
- `src/net.rs` — LAN basics without tools: IPv4 neighbours via netlink, default gateway (/proc/net/route), unprivileged ICMP ping (needs `net.ipv4.ping_group_range`; if forbidden STALE counts as online), reverse DNS (getnameinfo), virtual-interface name filter. Test: `cargo test net_dump -- --ignored --nocapture`. mDNS test: `cargo test mdns_dump -- --ignored --nocapture`.
- Devices screen: tabs Yours (Bluetooth, LAN, Wi-Fi of yours) / Others (other Wi-Fi, unnamed APs), `App.scope` = tab; groups (`collapsed`) all start closed; filter chips Wi-Fi/Bluetooth/LAN + Hide unnamed.
- Radar tray: `on_radar(d)` (= has a dBm reading, or a connected Bluetooth device) decides radar vs tray; everything else (LAN, disconnected Bluetooth) is listed in the right-hand tray (`App::tray`), grouped by `tray_group` (icon kind) then by name; click opens the info box beside the row (`radar_anchor`), no dragging. Saved drag positions stay in `over`, so a Bluetooth device that connects returns to its saved/calculated spot.
- Spectrum bottom panel "YOUR NETWORK" is drawn, not described: your network's name and channel, then one tile per clean channel (1/6/11 only; your network is a bigger dot, listed first, in every tile it is on or overlaps, no "yours" pill or ring, and no "quietest" check: the gauges show that) with a crowding gauge, one dot per other network heard there (glowing dot = on exactly this channel, dimmer flat dot = partly overlapping; colour as its hill and its row in the list; hovering a dot names it), hover gives the plain-text detail. The old help cards were removed. Hill/bar scale is `data::signal_frac` (-100..-10 dBm).
- Spectrum peak labels are cut in the middle (`fit_middle`) so they stay inside the graph, placed before hover detection so hovering a label hovers its hill (full name in the popup); list dots glow like the sidebar legend; the axis labels "dBm" and "Wi-Fi ch" are both cyan.
- Spectrum hover: graph picks the hill whose outline is nearest the cursor (ties: stronger), tooltip lists other hills stacked there ("Also here"); legend lists all networks and scrolls with the wheel.
- `src/demo.rs` — `AIRSCOPE_DEMO=1`: invented Wi-Fi/BT/LAN data through the same conversion fns (`wifi_dev`, `parse_bt`+`attach_link`, `lan_dev`); hides real hostname, saved positions, mine.txt. `AIRSCOPE_SHOT=<file.ppm>` grabs the app's own frame after 7 s and exits. `scripts/demo-shots.sh` renders README screenshots into `docs/screenshots/` inside headless `cage` (nothing on screen, nothing real captured).
- `src/snoop.rs` — native reader for `btmon -w` captures (btsnoop monitor format, no btmon needed; file may still be growing, `feed` resumes): connect/disconnect events with reason, `quiet` = time since last data packet, sniff-exit requests and controller answer time, bursts, per-device stats. Tests: `cargo test snoop`; `AIRSCOPE_SNOOP=<file> cargo test snoop_dump -- --ignored --nocapture`. Disconnect of a link up before the capture began gets `UNKNOWN` address.
- Date format everywhere in the UI and reports: `MMM d, YYYY` ("Nov 8, 2026") via `snoop::date`; times are 24 h. File names keep ISO (`snoop::date_iso`, session folders `YYYY-MM-DD_HH-MM-SS`); `snoop::pretty_stamp` shows a session folder name in the UI format.
- `src/diag.rs` — Diagnostics screen (4th nav item, `AIRSCOPE_SCREEN=diag`, `AIRSCOPE_SNOOP=<file>` opens a capture at start, `AIRSCOPE_TAB=1` the Timeline tab): open/drag-drop a capture, Summary tab (tiles, drops strip, device cards; the strip merges drops within 6 px into one wider tick with a dot, faint vertical gridlines on round local times (step picked from the whole span, 4-10 lines; labels only where they fit; start and end times at the edges; when the span crosses midnight the start and the first label of each later day carry the date), hovering a tick shows the shared boxed tooltip: device + date/time for a single drop, a list of device + time for a group; `Diag.tip` hands the `TipC` to `App::tip_want`; `AIRSCOPE_STRIP_HOVER=<tick index>` fakes the hover for screenshots) and Timeline tab (table: Time / Since start / Device / Event, newest first, only visible rows drawn, row heights from measured text width; file read in 4 MB chunks per frame, then only new bytes every 2 s; analysis cached per record count), Copy report, Save report to `~/.local/share/airscope/reports/`; reporting only. Record button (red, left of Open; length chosen in a dropdown, 15 min to 12 h) starts a capture through `capture.rs`, opens it live when btmon has written its header (LIVE lamp while data is arriving, REC lamp with time left while recording); Stop asks for the password again; at startup `capture::adopt` (reads /proc for a `btmon -w <library>/capture.snoop`, time left from `meta.tsv`) picks up a recording still running from an earlier run of the app, so REC/Stop come back (btmon outlives the app); a third tab, Library, lists saved sessions (Open, Copy path). A capture in the library keeps `report.md` and `summary.tsv` next to it (written when a recording ends or the capture is opened and fully read); Save report writes `report.md` there, other captures save to `~/.local/share/airscope/reports/`. Headless screenshot: `cage` as in `scripts/demo-shots.sh`.
- `src/capture.rs` — recording and the session library (no UI). `Recording::start(cap)` runs `pkexec /usr/bin/timeout <secs> /usr/bin/btmon -w <file>` (desktop password prompt; our own code never runs as root; the capture file is created first by us so it stays user-owned). `poll` -> Running/Finished/Failed (126 = prompt dismissed, 127 = no polkit agent; an empty session is removed). `stop` = `pkexec kill -TERM <pid of btmon>` (pid found by scanning /proc) or kills the waiting pkexec if not yet authorised. Sessions: `~/.local/share/airscope/captures/<YYYY-MM-DD_HH-MM-SS>/{capture.snoop,meta.tsv,summary.tsv,report.md}`. Tests: `cargo test capture`. The password flow itself can only be tried by hand (needs a polkit agent).
- `src/picker.rs` — file chooser via the desktop portal (`org.freedesktop.portal.FileChooser`) over session D-Bus with zbus (no extra dependency; KDE's own dialog on Plasma; would also work in a Flatpak). `Pick::start` runs it on a thread, `poll` each frame. Used by the vendor-list import and the Diagnostics Open button; drag-and-drop still works as the fallback.
- `src/fx.rs` — theme colours + custom painting: mesh gradients (`sphere`, `glow`, `glow_rect`), `panel`, `orb`, `dot`, `icon`, `lcd`, `led_bar`. Toolbar widgets shared by Devices and Diagnostics: `action_button` (glass pill), `view_tab` (underlined tab), `toggle_chip` (lamp toggle). Screen layout pattern: row 1 = what you work on (search / file) + actions or status on the right, row 2 = tabs left + filter chips right (no "SHOW" label).
- `src/main.rs` — everything else: `App`, `radar()` (latch/ping, grouping, layout shifts, drag), `spectrum()`, `devices()`, `popup()`, tooltips (`TipC`), `nets()`/`hill()` Wi-Fi model.

## Behaviour to keep in mind
- Radar data is *latched*: a device updates only when the sweep passes it, signal changes < `SIGNAL_LEEWAY_DB` (4 dB) are ignored; frozen while a group is open or a drag is active.
- Distances are signal-derived (log radial map); user drags saved in `~/.config/airscope/positions.tsv` (id, angle, metres). Optional extra "mine" SSID prefixes: `~/.config/airscope/mine.txt`. "Mine" Wi-Fi = BSSID derived from a LAN device MAC (`same_device`).
- Groups: union-find, GROUP_PX=38 on screen; stable keys via member overlap; click expands, drag moves all members; dragged node/group is excluded from merging until dropped.
- Ids must be unique: a router's BSSID can equal its LAN MAC; `sync()` suffixes the later duplicate (`~lan`). Animation state maps are keyed by id — duplicates broke grouping once.
- Info box (`popup`) and tooltips are shared across screens and fade (`pops`, `tip_want`).
- Window: 4x MSAA requested (`window_options`); `main` catches a failed start (eframe errors or panics when no MSAA config exists) and re-execs itself with `AIRSCOPE_FALLBACK=1` (no MSAA); `AIRSCOPE_MSAA=<n>` overrides the count (0 = off). Debug env switches: `AIRSCOPE_DEMO` (`=bad`: keyboard red, headphones amber), `AIRSCOPE_SHOT`, `AIRSCOPE_VENDOR`, `AIRSCOPE_ZOOM`, `AIRSCOPE_SCREEN=spectrum|devices`, `AIRSCOPE_SEL=<id>`, `AIRSCOPE_DEMO_CHAN=<n>` (demo: put "Maple House" on channel n, to test the Spectrum tiles), `AIRSCOPE_PIN_BIG`, `AIRSCOPE_AUTO`, `AIRSCOPE_SLOW`.
- Responsive layout (min window 1000x640; check headless with `cage` + `wlr-randr --output HEADLESS-1 --custom-mode WxH`): header chips pick one of three texts (full / count only / name only) that fits beside the title, always with a tooltip and no hand cursor, and Vendor list / Rescan become icon-only when even names don't fit (`header()`); Diagnostics row 1 turns Record/Stop/Open/Copy/Save into icon-only buttons with tooltips below ~930 px of content width and middle-truncates the filename (`fit_middle`, full name on hover); Devices filters are plain chips ("LAN" for network) with state tooltips and no "SHOW" label; Spectrum legend width = 22% of the window (150–300 px) with middle-truncated names; radar zoom block has a reset icon (was "1:1"). `toggle_chip` takes a tooltip, `icon_label`/`action_button` centre the icon when the label is empty.
- Testing: screenshot with `spectacle -b -n -a -o <file>`; don't screenshot while Peter is using the screen (once captured his browser — deleted).

## Portability roadmap (goal: no external tools)
Done: HCI (`hci.rs`), BlueZ D-Bus, NetworkManager D-Bus (stated requirement for Wi-Fi; nl80211 fallback only if someone asks), native LAN (`net.rs`, mdns-sd). Embedded OUI DB + user import done. AppImage done: `packaging/build-appimage.sh` (podman, Ubuntu 22.04 → needs glibc 2.35; GUI libs come from the host; output `dist/Airscope-x86_64.AppImage`, ~6 MB). Releases: push tag `vX.Y.Z` matching `Cargo.toml` (and `Cargo.lock`, `cargo test --locked` runs in CI) → `.github/workflows/release.yml` builds + publishes the AppImage and checksum (works: v0.2.0, v0.2.1 succeeded). Current version 0.2.3. README/LICENSE (MIT, Peter Epp) done. No Flatpak by choice (AppImage only; app needs system D-Bus, HCI sockets, LAN).

## Not done yet
Problems: `hci::watch` (unprivileged HCI socket, Connection/Disconnection Complete only — kernel blocks Mode Change/Completed Packets without root) feeds per-device drop events with reason codes (`hci::reason`); `data::apply_events` fills `Dev.issue` and sets two levels: red `Dev.trouble` (radio-reason drops; ≥3 reconnects in 10 min; another device dropping within 2 s = "Shared cause" note) and amber `Dev.caution` (≤22 usable channels, battery ≤ 15%); low link quality (< 75% of own 30-min best) and weak RSSI (≤ -10) are NOT flags on their own, they only add notes/severity when a radio-reason drop happened in the last 15 min (a device can work fine on a low reading); `apply_events` takes `peers` (id, name, events of all devices); the popup shows a glowing ring+dot indicator (red issue / amber warning, tooltip says which), a battery icon (BT, when known) and for connected BT three meters LINK / SIGNAL (RSSI relative to ideal range, NOT dBm: absolute dBm needs inquiry scanning, which disturbs the shared radio) / CHANNELS; info box shows an ISSUE button by the name that toggles an inner box with `Dev.issue` (closes on click outside); Devices list rows end with CONNECTED label, one unit-less strength bar (Wi-Fi dBm, or `data::bt_quality` = the weaker of link quality and RSSI for Bluetooth) and the ISSUE/WARNING chip; clicking anywhere outside the info boxes closes the open one (selection unchanged this frame = click on nothing); `led_bar` segments use `glow_rect`; link quality shown as % (`data::lq_pct`); boxes scroll with a visible scrollbar and `App.wheel`/`popup_rects` route the wheel to the box under the mouse instead of zooming the radar. `AIRSCOPE_ISSUE=1` opens the inner box at start. Root capture is done by pkexec-ing the system btmon (see `capture.rs`), not by a helper of ours (AppImage+pkexec FUSE problem avoided); `setcap` on a copy of btmon would allow a Stop without a second password (untested idea). Halo: red/amber pulsing (also rings a group containing such a device); no legend entry until seen on real hardware; `AIRSCOPE_DEMO=bad` fakes one. Not done: settings panel, LAN scan button, `.desktop` launcher, reset-positions option.
